# beiguo-market-research

`beiguo-market-research` 是一个面向 Codex 的市场调研、产品调研、用户研究和商业机会判断 Skill。

它不是用来生成泛泛的行业报告，而是把一个具体市场里的「人、货、钱、路、规则、历史变化」拆开，再落回到你的产品、服务、用户群体、渠道、定价和交付能力上，帮助你判断下一步到底该做什么。

## 入口名称

安装后，在 Codex 的 `/` 菜单里显示为：

```text
/beiguo-market-research
```

Skill 的内部名称也是：

```text
beiguo-market-research
```

对应配置在：

```text
beiguo-market-research/agents/openai.yaml
```

## 适合解决什么问题

- 我想进入一个新市场，但不知道机会是否真实。
- 我有一个产品想法，需要判断用户是否真的愿意付钱。
- 我想做城市、门店、渠道、品类或用户群体调研。
- 我需要一份线下访谈提纲、田野调研计划或调研报告大纲。
- 我想分析竞品、替代方案、购买链路、渠道进入难度和定价空间。
- 我已经有一些零散观察，希望整理成可行动的产品机会判断。

## 不适合做什么

- 不适合直接生成没有证据来源的宏观行业报告。
- 不适合只用公开资料给出确定性结论。
- 不适合跳过用户业务背景，直接推荐产品方向。
- 不适合把「用户说需要」直接当成真实需求。

这个 Skill 会优先追问你的具体业务场景，再决定应该调研什么、怎么验证、证据强度够不够。

## 核心方法

`beiguo-market-research` 默认采用 Beiguo-style 市场调研方法：

- 先定义决策问题，而不是先写报告。
- 先深挖一个典型样本，而不是泛泛覆盖很多样本。
- 优先找内部知情人，而不是只问方便回答的人。
- 记录具体品类、价格、销量、毛利、费用、渠道和交易规则。
- 区分用户、购买者、付款者、影响者、审批者和失败风险承担者。
- 追问真实替代方案，而不是只问「你需不需要」。
- 用证据等级标注结论可信度。
- 最终必须转成产品行动建议。

## 安装

克隆仓库：

```bash
git clone https://github.com/mufengDiamond/beiguo-skill.git
```

复制 Skill 到 Codex 的 skills 目录：

```bash
cp -R beiguo-skill/beiguo-market-research ~/.codex/skills/
```

如果你使用自定义 `CODEX_HOME`：

```bash
cp -R beiguo-skill/beiguo-market-research "$CODEX_HOME/skills/"
```

安装后重启 Codex，或刷新 Skill 加载。刷新后可以在 `/` 菜单中搜索：

```text
beiguo-market-research
```


## 输入信息建议

为了让调研结论更具体，最好提供这些信息：

- 你想做的产品或服务是什么。
- 目标用户是谁。
- 当前客户或种子用户是谁。
- 所在行业、品类、城市、渠道或平台。
- 当前价格、预期价格或收费方式。
- 你现在的获客方式和交付能力。
- 你想支持的决策是什么，例如进入市场、改产品、定价、选渠道或做 MVP。
- 你已有的证据是什么，例如访谈、订单、转化率、用户反馈、竞品观察。

如果你没有这些信息，Skill 会先帮你追问和补齐。

## 输出内容

根据任务不同，Skill 可以输出：

- 调研目标和决策问题
- 关键调研问题
- 典型样本选择理由
- 访谈对象地图
- 用户访谈提纲
- 田野观察清单
- 市场结构图
- 品类、价格、销量、毛利和交易规则分析
- 购买链路与利益相关者分析
- 竞品和替代方案分析
- 付费意愿判断
- 渠道进入难度判断
- 产品机会评分卡
- MVP 验证计划
- 风险清单和下一步行动建议

## 证据等级

重要判断会按证据强度标注：

- `A`：真实付款、订单、合同、留存、使用记录或现场交易。
- `B`：多角色交叉验证，或一个角色加可观察证据。
- `C`：单一访谈口述，可信但尚未验证。
- `D`：公开报告、媒体、平台数据或行业 benchmark。
- `E`：推断或假设，只适合用于规划下一步验证。

`SKILL.md` 中的 `name` 是系统内部识别名：

```yaml

```

`agents/openai.yaml` 中的 `display_name` 是 Codex `/` 菜单里展示的名称：

```yaml

  display_name: "beiguo-market-research"
```

如果你想让 `/` 菜单显示中文名，可以改这里；如果你想让菜单和内部名一致，就保持当前配置。

## 设计原则

好的调研不是把行业讲得很大，而是把一个具体决策变清楚。

这个 Skill 默认追问：

- 用户是谁？
- 他现在怎么解决？
- 谁真的付钱？
- 为什么现有方案不够好？
- 他愿意为更好方案付多少钱？
- 你能不能触达他？
- 你能不能交付？
- 什么证据说明应该继续？

最终目标是把市场事实翻译成产品行动：做、不做、缩小人群、改 offer、改价格、换渠道、先验证，或等待更多证据。
